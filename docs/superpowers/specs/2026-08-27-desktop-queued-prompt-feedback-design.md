# 桌面端排队消息即时反馈设计

## 背景

桌面端提交、提升或取消排队消息后，daemon 已经返回权威结果，但主进程把响应丢弃为 `void`，渲染进程只能等待 SSE 更新完整会话。SSE 正常时会出现短暂空窗；SSE 重连时，输入框已经清空但队列没有变化，用户会认为操作没有生效。

## 目标

- 普通发送一经客户端接收，立即显示在待处理区域，不等待 SSE。
- 提升或取消一经 daemon 确认，原队列项立即从待处理区域消失。
- SSE 仍是最终权威来源；到达后自动接管，界面不重复、不闪回。
- 操作失败时保留原消息，并在对应队列区域显示可理解的错误。
- 一个会话的操作状态不能锁住或污染另一个会话。

## 方案

采用“服务端快照 + 本地确认覆盖层”。`sessionView` 继续只保存 SSE/snapshot 的权威状态；store 另存本地覆盖状态，不直接伪造 cursor。

覆盖层包含两类数据：

1. `localQueuedPrompts`：已提交但 SSE 尚未确认的输入和 run。提交接口返回真实记录后写入；当 `applySessionUpdate` 中出现相同 input/run，自动移除。
2. `queuedPromptActions`：按 `sessionId + runId` 记录 `promote` 或 `cancel`。daemon 确认后把 run 标记为本地隐藏；当 SSE 显示该 run 已进入终态或消失，自动移除覆盖状态。

界面展示值由 `sessionView` 与覆盖层合并得到：相同 run 只显示一次，本地隐藏的 run 不显示。这样即使较旧 SSE 稍晚到达，也不会把已确认的操作重新显示出来。

## 数据流

### 普通发送

1. 用户提交后立即建立 `submitting` 本地项，输入框可清空并展示“正在发送”。
2. IPC 返回 daemon 的 `PromptResponse` 后，用真实 input/run 替换临时项。
3. SSE 包含相同 input/run 后，删除本地项，继续显示权威项。
4. IPC 失败时删除临时项，保留输入草稿，并显示错误。

### 调整方向与取消

1. 点击时只锁定被操作的 run。
2. daemon 成功后立即隐藏该 run；SSE 到达后清理本地隐藏标记。
3. daemon 失败时解除锁定、保留消息，并在队列区域显示错误。
4. 如果失败原因是活动 run 已变化，提示“当前回答已经切换，这条消息仍保留在待处理队列中”。

## 会话隔离

所有本地状态都带 `sessionId`。切换会话时，旧请求可以继续结束，但只能更新其所属会话的覆盖状态；不能禁用新会话按钮，也不能把旧会话错误显示到新会话。

## 测试

- HTTP/IPC 成功、SSE 未到：发送项立即可见。
- SSE 先到、IPC 后返回：不出现重复项。
- promote/cancel 成功、SSE 未到：原项立即隐藏。
- 操作失败：原项保留且错误可见。
- 操作过程中切换会话：新会话不被锁定，旧结果不污染新会话。
- SSE 最终到达：覆盖状态被清理，权威状态接管。

## 非目标

- 不改变 daemon 的排队、幂等或 steer 语义。
- 不在本次重构整个桌面同步框架。
- 不允许客户端生成假的服务端 cursor。
