# 大文件源码预览后台高亮设计

## 背景

右侧文件面板已经使用 Pierre `Virtualizer`，屏幕上只会创建可见区域附近的代码行。但语法高亮仍由 Shiki 在 Electron 渲染进程的主线程中处理，而且 Pierre 在高亮模式下会先分析完整文件，再把结果交给虚拟列表。

实际复现文件 `hermes-runtime-map.html` 约 742 KB、15,000 行，最长一行约 26,586 个字符。打开该文件时，完整 HTML 高亮会长时间占用界面线程，导致滚动、点击和面板切换看起来全部卡死。

## 目标

- 大文件打开后立即看到源码，不等待语法高亮。
- 高亮期间桌面客户端仍可滚动、点击和切换面板。
- 后台高亮完成后，自动把纯文本源码替换成高亮源码。
- 继续使用 Pierre `Virtualizer`，避免一次创建全部代码行的 DOM。
- 保留大 HTML 的“在内置浏览器中打开”操作。

## 不做的内容

- 不实现按可视区域增量解析 HTML 语法。
- 不替换 Pierre 或 Shiki。
- 不修改 Markdown 预览和 HTML 浏览器的行为。
- 不为了大文件预览重构整个右侧工具面板。
- 不保证 15,000 行 HTML 的完整高亮瞬间完成，只保证高亮期间界面不会卡死。

## 方案比较

### 方案 A：大文件永久使用纯文本

实现最简单，也能完全避开 Shiki 卡顿，但不满足“源码最终仍然高亮”的要求，因此不采用。

### 方案 B：主线程延迟执行 Shiki

先显示纯文本，再通过 `requestIdleCallback` 或定时器启动高亮。它只能把卡顿推迟，Shiki 开始工作后界面仍会卡住，因此不采用。

### 方案 C：纯文本立即显示，Worker 后台高亮

先用 Pierre 虚拟列表显示纯文本，再使用 Pierre 自带的 WorkerPool 在后台执行 Shiki。完成后自动替换显示内容。这能保留最终高亮，同时避免阻塞界面线程，采用此方案。

## 运行流程

所有源码预览统一使用 Worker，不增加大文件阈值和两套渲染路径：

1. 文件内容进入 Pierre 文件组件。
2. Pierre 立即为当前可见区域生成纯文本结果。
3. `Virtualizer` 显示纯文本，用户可以立即滚动、选择和复制。
4. Pierre 同时把完整内容交给 WorkerPool。
5. Worker 在线程外初始化 Shiki、识别语言并生成高亮结果。
6. Worker 完成后，Pierre 自动把当前文件更新为高亮结果。
7. 文件切换或组件卸载时，由 Pierre 清理对应任务，旧结果不会覆盖当前文件。

普通小文件也走同一条路径。它们的后台高亮通常很快，可以避免维护阈值，也能防止行数不多但语法结构复杂的文件阻塞界面。

## 超长行保护

Shiki 对极端超长行的正则分析成本很高。设置 `tokenizeMaxLineLength` 为 4,000 个字符：

- 不超过 4,000 字符的行正常高亮。
- 超过 4,000 字符的单行按普通文本显示。
- 其他行不受影响。

这不会截断内容，也不会改变复制结果，只是不为该行生成彩色语法标记。

## 组件边界

### `VirtualizedCodePreview`

继续负责源码显示和滚动定位。组件不自行维护纯文本、高亮完成或请求标识；这些状态由 Pierre 的 `VirtualizedFile` 和 WorkerPool 管理。

### Pierre Worker Provider

在文件预览组件的稳定上层创建一次 Pierre `WorkerPoolContextProvider`。Worker 池不随文件切换反复创建，避免重复加载 Shiki 语言和主题。

首版只创建 1 个 Worker。右侧面板同一时间只需要高亮当前文件，更多 Worker 会额外占用内存，没有实际收益。

## 状态与错误处理

使用 Pierre 已有的任务清理、缓存和结果更新机制，不额外创建 React 请求队列。Worker 初始化或单次高亮失败时，已经显示的纯文本保持可用；错误记录到现有日志，不增加遮挡源码的错误页面。

## 验收标准

- 打开 15,000 行的 `hermes-runtime-map.html` 后，源码应立即出现。
- 后台高亮期间可以正常滚动、点击按钮、切换文件和切换右侧工具。
- 高亮完成后自动显示语法颜色，不需要用户再次操作。
- 第 4,965 行约 26,586 字符的内容完整保留，但该行不要求语法着色。
- 快速切换文件时，旧文件的高亮结果不会覆盖当前文件。
- Worker 初始化或高亮失败时，仍可继续查看、滚动和复制纯文本。
- 普通小文件的现有高亮行为不变。

## 验证范围

- Worker 配置测试：单 Worker、Shiki 高亮器和 4,000 字符单行上限。
- 源码预览测试：组件处于 Worker Provider 内，文件参数和现有滚动行为不变。
- 使用真实的 15,000 行 HTML 做桌面端手工验证，观察界面响应和最终高亮。
