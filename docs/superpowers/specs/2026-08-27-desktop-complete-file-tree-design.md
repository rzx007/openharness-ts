# Desktop 完整文件树设计

## 背景

桌面端右侧文件面板通过 `WorkspaceService.listFiles()` 扫描项目，再把路径传给 `@pierre/trees`。当前主进程最多收集 5,000 个文件或目录；达到上限后停止扫描，并由渲染进程显示“文件较多，仅显示前 5000 项”。因此，大型项目的文件树缺少后续条目。

`@pierre/trees` 已内置行虚拟化：页面只挂载视口中的行和少量缓冲行。现有配置中的 `initialVisibleRowCount: 36` 控制首次测量前的渲染预算，`overscan: 18` 控制视口外的缓冲行；它们不会限制树中的数据总量。问题来自扫描阶段截断，而不是渲染阶段没有虚拟化。

## 目标

- 展示当前项目内所有未被现有规则忽略的文件和目录。
- 移除 5,000 项硬上限及对应的截断提示。
- 继续使用 `@pierre/trees` 已有的虚拟化能力，不引入另一套虚拟列表。
- 保留现有排序、搜索、选择、右键菜单和刷新行为。

## 非目标

- 不实现展开文件夹时才读取内容的异步目录树。
- 不修改现有忽略规则；`.git`、`node_modules`、`dist` 等目录仍不进入文件树。
- 不为超大型仓库增加新的分页或数量上限。
- 不调整文件预览的大小限制。

## 方案

### 主进程扫描

删除 `WorkspaceService.listFiles()` 中的 `maxEntries` 常量、提前返回判断和 `truncated` 状态。递归扫描继续按现有方式工作：每个目录先展示子目录，再展示文件；同类条目按名称排序；符号链接和忽略目录不进入结果。

扫描完成后，主进程返回完整的 `entries`。首次读取大型项目可能比原先更久，因为原先在 5,000 项时提前结束；这是展示完整文件树所必需的成本。

### IPC 数据契约

从 `WorkspaceListFilesResult` 删除 `truncated`。该字段只描述被移除的 5,000 项限制，解除限制后固定返回 `false` 没有业务意义。

IPC 入口与预加载桥仍调用同一个 `listFiles` 方法，不增加分页参数或新的调用。

### 渲染进程

`FilesTool` 继续从完整的 `entries` 建立文件映射和路径数组。`ProjectFileTree` 继续使用 `prepareFileTreeInput(...)` 生成 `preparedInput`，并把它交给 `useFileTree(...)`。

保留以下虚拟化相关配置：

- 固定高度的树容器 `style={{ height: "100%" }}`；
- `initialVisibleRowCount: 36`；
- `overscan: 18`；
- `density: "compact"`。

删除依赖 `listing.truncated` 的底部提示。文件树滚动时仍只挂载可见行和缓冲行，完整路径集合保存在树模型中。

## 数据流

1. 用户打开项目或刷新文件树。
2. 渲染进程调用 `window.desktop.workspace.listFiles({ rootPath })`。
3. 主进程递归读取所有未忽略的目录和文件，并返回完整条目列表。
4. 渲染进程提取路径并准备 `@pierre/trees` 输入。
5. `FileTree` 根据面板实际高度虚拟化渲染可见行。
6. 用户展开、搜索或滚动时，树模型更新可见路径窗口，不重新扫描磁盘。

## 错误处理

保持现有错误边界：根目录无效、目录读取失败或 IPC 调用失败时，`FilesTool` 进入错误状态并显示错误信息。解除数量上限不改变错误格式。

单个文件的 `stat` 失败时仍保留该文件条目，只省略 `size`。扫描目录失败仍由整个 `listFiles` 调用向上抛出，与当前行为一致。

## 测试与验证

按 TDD 增加 `WorkspaceService` 回归测试：

1. 创建超过 5,000 个文件的临时项目，断言返回数量超过 5,000 且包含末尾文件。该测试在当前实现上应因截断而失败。
2. 验证现有忽略目录仍不会出现在结果中，避免解除限制时扩大扫描范围。
3. 验证目录优先和名称排序行为保持不变。

实现后运行桌面端相关测试、Node 与 Web TypeScript 类型检查，以及针对修改文件的 ESLint 检查。最后检查差异，确认没有覆盖工作区中已有的无关修改。

## 取舍

完整扫描会增加大型项目首次加载时的磁盘读取、IPC 传输和树输入准备成本，但渲染 DOM 的规模仍由 `@pierre/trees` 虚拟化控制。相比提高上限，这个方案不会在更大的仓库中再次静默缺失文件；相比按需目录加载，它不需要重构 IPC、搜索和刷新语义，范围与当前缺陷相匹配。
